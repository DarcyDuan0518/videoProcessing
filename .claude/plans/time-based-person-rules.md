# 增加深夜直删与过渡时段两人保留规则

## 目标

在 `keep_videos_with_person=false` 时，实现固定的三段逻辑：

| 文件名录制开始时间 | 行为 |
| --- | --- |
| 23:00（含）–次日 07:00（不含） | 直接列为可删除候选，不解码、不推理。 |
| 21:00（含）–23:00（不含）和 07:00（含）–08:00（不含） | 正常推理；仅当任一采样帧同时检测到 **至少 2 人** 时保留，否则列为可删除候选。 |
| 其余时间 | 正常推理；任一采样帧检测到 **至少 1 人** 即保留。 |

在 `keep_videos_with_person=true` 时保留既有语义：不做夜间或过渡时段特判，全部视频按“任意检测到 1 人即保留”处理。

## 实施步骤

1. 扩展 `night` 配置模型，使规则可配置、而不是把 21/23/07/08 写死在代码中：
   - `direct_candidate_start: "23:00"`
   - `direct_candidate_end: "07:00"`
   - `two_person_windows`：默认两个区间 `21:00–23:00`、`07:00–08:00`
   - 继续使用 `keep_videos_with_person` 开关。
   - 增加类型、时钟格式和每个时段开始/结束值的校验；时段端点采用开始含、结束不含。

2. 调整 `video_sorter.py` 的时间分类及结果判定：
   - 通过一个时间策略帮助函数将视频归为 `direct_candidate`、`two_person_required`、`normal` 或 `not_checked`。
   - 仅 `direct_candidate` 跳过解码/推理，并在报告中使用明确的处理模式与原因。
   - 对过渡时段推理结果，使用已有 `max_person_count`：`>=2` 显示“检测到人”并保留；`0` 或 `1` 显示“可删除候选”。
   - 保持 `is_night` 报告列可读，并使 `processing_mode` 区分直删、两人阈值推理和普通推理。
   - 更新控制台统计文字，分别显示深夜直入候选、过渡时段两人识别与普通识别数量。

3. 更新 `config.json` 为用户明确的默认窗口，并更新配置/部署/README/Agent 文档说明和报告字段含义。

4. 验证：
   - 用纯 Python 单元式检查覆盖边界 `21:00`、`22:59:59`、`23:00`、`06:59:59`、`07:00`、`07:59:59`、`08:00` 以及 `keep_videos_with_person=true`。
   - 用构造的 `VideoResult` 验证过渡时段的 0、1、2 人分类，确认只有 2 人保留。
   - 执行 Python 编译、JSON 加载和 `git diff --check`。
   - 不运行候选移动脚本，不移动用户视频。
